# 월간 쿠피 관리자 변경 — 2026-10-25

운영 서버/웹 배포는 아직 하지 않았다. 사용자 직접 커밋·푸시 원칙을 유지한다.

## 운영 순서

1. 별도 **월간 쿠피 → 월간호 · 회차** 메뉴에서 언어별로 생성하고 발행 월(YYYY-MM), 제목, 대표 표지를 지정해 공개.
2. 회차별 본문/표지와 공개 일시를 등록하고 예약 저장. 한국 시간 예약 시각 전에는 앱에서 숨기고 다운로드도 차단.
3. 일괄 등록에서 시작 일시와 발행 간격을 입력하고 일정 적용. 회차 번호순으로 배정되며 개별 일시 수정 가능. 발행 월을 넘기는 행은 등록 불가. 과거 일시는 즉시 공개.
4. 월간호에서 월말 자동 합본 생성을 켜고 공개일 기준을 확인한 뒤 수정하고 공개. 월이 끝난 후 매시간 확인하여 해당 월에 공개된 회차가 있으면 합본 자동 생성.
5. 조기 마감은 지금 합본 만들고 마감 버튼 사용. 해당 월에 현재 공개된 회차만 포함. 직접 만든 합본 연결도 유지.
6. 다음 달 작품은 새로 등록. 빈 월간호는 자동 생성하지 않는다.

합본이 실제 공개된 경우에만 연재 목록을 합본으로 전환한다. 회차 다운로드와 이미 받은 책·독서 기록을 삭제하지 않는다. 합본이 비공개가 되면 기존 연재 목록이 복구된다. 앱의 합본 안내는 연결 시점부터 30일, 확인했어요로 해당 기기에서 숨김 가능.

## 변경 파일

- components/admin/reader/MonthlyFields.tsx: 발행 월/일, 같은 언어·월의 공개 EPUB 합본 선택.
- ReaderContentManager.tsx: 월간 메타데이터 편집 및 보존.
- ReaderEpisodeBatch.tsx: 시작 일시·간격으로 예약 배정, 행별 수정·검증.
- lib/admin/firebase/reader-api.ts: issueMonth, releaseDate, releaseAt, compilationId.

## 배포 의존성

먼저 Koofy-Reader의 Firebase Functions 변경을 배포한 뒤 이 웹을 배포한다. 이어 앱 업데이트가 필요하다. 이후 회차 발행에는 앱 재빌드가 필요 없다.

전체 설계·EPUB 제작 규칙·앱 변경과 검증은 형제 저장소 Koofy-Reader/docs/monthly-koofy.md 참고. 합본은 파일당 20MiB 제한이므로 이미지 용량을 조절한다.

## 별도 메뉴

`/admin/projects/koofy-reader/monthly`에서 월간호·회차·합본을 모두 관리한다. 기존 책·표지 메뉴는 일반 도서/연재만 표시한다. 기존 월간 콘텐츠는 이동·복제하지 않고 발행 월 기준으로 자동 분류한다. 이번 메뉴 분리는 웹 변경만 배포하면 되며 서버·앱 재배포는 필요 없다.

## 공개 시각 예약 패치

기존 월간 쿠피 앱이 설치되어 있다면 이번 예약 기능 때문에 앱을 재빌드할 필요는 없다.
서버를 먼저 배포한 뒤 웹을 배포한다. 날짜만 있는 기존 회차는 한국 시간 자정 공개를 유지한다.
관리자 일정 테스트 3개, TypeScript 검사 및 프로덕션 빌드 통과.
예: 10개 회차 선택 → 11월 5일 09:00 시작 / 간격 1일 → 일정 적용 → 11월 5~14일 예약 확인 → 등록하고 예약·공개.
후속 패치에서 TXT·이미지 EPUB 자동 생성과 월말 자동 합본을 추가했다. 아래 참고.

## 회차 · 합본 EPUB 자동 제작

1. 같은 이름의 TXT와 회차 이미지를 등록한다. `[장]` 없이 빈 줄로 문단을 구분한다. 이미지가 첫 장, 이후 본문인 EPUB을 공개 시 생성한다. 글쓴이는 선택 입력하며 이미지 위에 표시한다.
2. 월간호에서 자동 합본을 설정하고 **수정하고 공개**한다. 초안 저장만으로 적용되지 않는다.
3. 다음 달 1일 한국 시간 0시 이후 매시간 확인한다. 해당 월에 공개된 같은 언어의 회차만 공개 일시 순으로 포함한다. TXT가 없는 EPUB 회차는 TXT를 등록하고 다시 공개해야 자동 합본에 포함된다.
4. 실패하면 기존 회차 목록을 유지하며 월간호 편집 화면에 이유를 표시한다. 수정 후 다음 실행을 기다리거나 마감 버튼으로 재시도한다.
5. 성공하면 합본 책을 공개하고 월간호를 완결로 연결한다. 회차·사용자 독서 기록은 삭제하지 않는다.

기존 월간호에는 자동 합본이 기본 꺼져 있다. 직접 켜고 공개일 기준을 확인한 뒤 공개해야 한다.
이번 서버 배포에는 `readerMonthlyCompilation` 예약 함수가 추가된다. `firebase deploy --project koofy-reader --only functions:reader`로 먼저 배포하고 웹을 배포한다. 기존 월간 기능이 있는 앱 재빌드는 필요 없다.
원본 TXT는 그대로 보관한다. 공개본은 EPUB이므로 새 다운로드에 이미지가 들어간다. 이미 다운받은 이전 TXT는 자동 교체하지 않는다.

## 월간호 등록 화면 정리

- 상단: 발행 월 · 언어 · 제목. 공개한 월·언어 잠금 유지.
- 본문: 표지 미리보기/파일 선택과 공개일 기준·자동 합본 설정을 2열로 배치. 작은 화면에서는 1열.
- 제작자·설명·배포 권한·직접 만든 합본 연결은 추가 정보에 접어서 배치. 필수 정보 누락은 고정 하단에서 안내하고 해당 영역으로 이동 가능.
- 초안 저장·공개 버튼은 화면 하단 고정. 비공개·삭제는 별도 접힌 관리 영역.
- 월간호 목록 선택은 회차 관리로 이동. 회차 화면의 월간호 설정 버튼으로 기본 정보 편집.
- 선택한 로컬 표지는 즉시 미리보기. 공개 표지는 현재 초안과 같은 파일일 때 공개 다운로드 API로 미리보기. 미공개 저장 표지는 파일 등록 상태를 표시하며 이전 공개 표지로 혼동시키지 않음.
- 전용 MonthlyIssueEditor 컴포넌트 사용. 일반 책·연재·글꼴 입력 흐름은 유지.
- 웹만 배포하면 되는 UI 변경. 커밋·푸시·배포는 사용자 진행.

화면 검증: 실제 컴포넌트의 로컬 미리보기에서 넓은 화면 2열과 390px 1열, 추가 정보 펼침, 고정 버튼 배치를 확인. 임시 미리보기 경로는 제거. TypeScript 검사 및 프로덕션 빌드 통과. 운영 데이터 등록·공개는 실행하지 않음.

## 예정 회차 수 제거

예정 회차 수 입력은 없다. 월간호에 속한 같은 언어의 공개 회차 중 한국 시간 해당 월 1일 00:00 이상, 다음 달 1일 00:00 미만의 공개 일시만 합본에 넣는다. 초안·비공개·삭제 중·다른 달·미래 예약 회차는 제외하고 마감을 막지 않는다. 공개 일시 순으로 정렬하며 예전 날짜만 있는 회차는 자정 기준이다. 대상 TXT 누락·파일 오류 시에는 기존 목록을 유지한다. 대상 0개이면 합본 생성하지 않는다.
이번 변경은 서버 먼저, 웹 다음으로 배포한다. 앱 재빌드는 불필요하다.

### 월간호 추가정보 기본값
발행자는 쿠피랩으로 자동 저장하고 앱에 노출하지 않습니다. 회차 글쓴이는 선택 입력이며 이미지 위에 표시합니다. 이용조건은 기본 문구를 제공하되 수정할 수 있고, 빈 값이면 서버 기본값을 적용합니다. 기존 수동 이용조건은 유지합니다.
